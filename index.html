01 — La solución

¿Qué es SIVU?

Una plataforma web que reemplaza el flujo manual de Excel, Word, correos y WhatsApp del proceso de Coformación por un sistema único donde cada actor trabaja en línea y los documentos se generan solos.

El problema (AS-IS)

Formatos GAC-FM-10/11/1, GAC-FM-007 y GTC-FM-16 en Excel/Word · envío por correo · seguimiento manual · el estudiante no ve el estado de su trámite · reuniones coordinadas por WhatsApp.

La solución (TO-BE)

Los 5 formatos se diligencian dentro de la plataforma y se generan como PDF oficial (logo, código, versión, firmas). Notificaciones automáticas, expediente digital, agendamiento colaborativo y asistencia con IA/MCP.

Los 4 actores del proceso

🎓 Estudiante

Diligencia plan, actas e informe; propone reuniones.

🧑‍🏫 Docente Acompañante

Evalúa cortes 1 y 2, gestiona su agenda, firma actas.

🏢 Tutor Empresarial

Evalúa el corte 3 con acceso externo por token (sin cuenta institucional).

🗂️ Oficina de Coformación

Asigna prácticas, supervisa, valida y consolida notas.

Los 5 documentos que digitalizamos

GAC-FM-11Acta de AcompañamientoLos 3 cortesPrellenada desde la reunión agendada
GAC-FM-1Evaluación del DocenteCortes 1 y 2PDF con los 2 cortes en columnas paralelas + nota acumulada

03 — Arquitectura global

Cómo se habla el stack

El navegador consume una API REST con JWT; el backend orquesta la lógica, dos bases de datos, la generación de PDF, la IA y el MCP. Cada push a master que pasa las pruebas se despliega solo.

Flujo iterativo de una petición — ejemplo: enviar el Plan (GAC-FM-10)

El estudiante llena el formularioFront

React valida con react-hook-form + zod y TanStack Query dispara POST /api/v1/…/plan-actividades con el Bearer JWT.

El backend autoriza y persisteBack

El filtro JWT valida el token, @PreAuthorize valida el rol, el servicio aplica reglas y guarda en PostgreSQL.

Los datos viven relacionadosBD

plan_actividades + plan_actividades_objetivo + plan_actividades_mes, colgando del trimestre del convenio.

Notifica y, al aprobar los 3, genera el PDFBack

Se disparan notificaciones (auditoría). Cuando estudiante+tutor+docente aprueban, OpenPDF genera el PDF oficial y lo cuelga del expediente.

El estudiante ve el estado en tiempo realFront

TanStack Query invalida la caché y el expediente refleja el nuevo estado y el PDF descargable.

Sí cumplimos despliegue continuo dockerizado: imágenes Docker en GHCR, backend + IA sidecar en Render (Dockerfile), frontend en Vercel, y el job CD despliega automáticamente tras el CI en verde.

04 — Persistencia poliglota

Base de datos

Cumplimos el requisito de la materia al pie: PostgreSQL para el core del dominio académico y otra tecnología (MongoDB) para los usuarios y la autenticación.

PostgreSQL · dominio

Estudiantes, empresas, tutores, convenios, trimestres, planes, actas, evaluaciones, informe final, calificación consolidada, agendamiento, notificaciones. Local en Docker · prod en Supabase (pooler JDBC + SSL).

MongoDB · usuarios

Colección usuarios: email, passwordHash BCrypt, roles y enlaces lógicos estudianteId / empresaId / tutorId. Local en Docker · prod en Atlas.

Convención de nomenclatura

Tablas

snake_case. Entidades principales en plural (estudiantes, convenios); detalle/relación en singular compuesto (plan_actividades, acta_reunion).

Llave primaria

Siempre id BIGSERIAL PRIMARY KEY — autoincremental, sin claves naturales.

Llaves foráneas

<tabla>_id → REFERENCES tabla(id) con ON DELETE CASCADE/SET NULL.

Metadatos

created_at / updated_at TIMESTAMPTZ DEFAULT now(); únicos uq_*; índices idx_*.

05 — El motor

Backend, IA, MCP y CI/CD

API REST en Spring Boot organizada package-by-feature (arquitectura por capas dentro de cada módulo: web → service → domain/persistence), con seguridad JWT, generación de PDF y dos integraciones de IA.

Arquitectura del backend

Package-by-feature

Cada dominio (estudiante/, convenio/, trimestre/, agendamiento/…) encapsula su web · service · domain · persistence.

Seguridad

JWT HS512 (login/refresh/registro), @PreAuthorize por rol y auto-scope estricto por dueño (docente/tutor/estudiante).

Robustez

Bean Validation, reglas de negocio en servicios, manejo centralizado de errores (@ControllerAdvice).

Documentación

Swagger UI en vivo + Flyway aplica migraciones al arrancar contra Supabase.

🤖 IA — ¿qué IA, para qué y cómo ayuda?

Qué: un IA Sidecar en Node que usa @anthropic-ai/claude-agent-sdk con el plan de Claude Code (sin gastar API key). Para qué: revisar cualitativamente el Informe Final (GTC-FM-16). Cómo ayuda: el estudiante pulsa “Revisar con IA” y recibe retroalimentación sobre coherencia, secciones vacías y calidad antes de enviarlo al docente.

Front: “Revisar con IA”Front

El editor del informe llama al backend.

Backend → SidecarBack

POST /ia/informe-final/{id}/feedback reenvía al sidecar en Render.

Sidecar → Claude CodeIA

El agente analiza el texto y devuelve feedback. Si el sidecar no está, el backend usa un revisor heurístico local (secciones vacías, límite 15 páginas, carátula).

Por features
